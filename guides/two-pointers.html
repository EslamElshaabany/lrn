The core idea
Two pointers = two indices scanning a sequence, moved strategically so you avoid brute-force nested loops. Instead of O(n²) "try every pair", you use structure (sorted order, a target sum, symmetry) to decide which pointer to move — giving you O(n).

The key question to ask yourself
"After I look at this position, can I eliminate one side completely?"

If yes → two pointers. The structure (sorted array, symmetry, a known target) tells you which pointer to move without checking everything else.
Pattern: start at both ends, shrink inward
Works when the array has symmetry or when moving a pointer in one direction provably can't hurt you. The insight: if the current pair doesn't satisfy the condition, move the pointer that gives you the best chance of fixing it.

Decision rule (opposite ends):
Move the pointer whose value is less useful to keep — e.g. in palindrome: always move both if match, return false if mismatch. In sorted squares: always take the larger absolute value from whichever end it's on.
Pattern: fast scans, slow writes
fast reads every element. slow (insert index) only advances when fast finds something worth keeping. This in-place filters/reorders without extra space.

Interactive — move zeroes

slow = insert index. fast finds non-zero values and swaps them to slow's position.
Decision rule (same direction):
fast always moves every step. slow only moves when fast finds a valid element (non-zero, non-duplicate, real character). Swap or copy fast→slow when valid. After the loop, slow is the new length.

Backspace compare — two simultaneous same-direction (from the right)

This one runs two independent "find next valid" scans, one per string, both moving right-to-left. The skip counter acts as a virtual stack — it counts pending backspaces without needing an actual stack data structure. This is why it beats the stack solution in space.

Interview strategy:
Start with the stack solution — it's easier to explain and code correctly under pressure. Then say: "If we care about O(1) space, we can do this with two pointers instead…" and explain the approach. That shows depth without risking a buggy implementation.
When stack beats two pointers
Stack wins when you need to remember past decisions (e.g. valid parentheses, min stack, largest rectangle in histogram). Two pointers only work when the array's structure lets you eliminate positions without needing history.
When two pointers beats stack
Whenever O(1) space is required. Or when the interviewer says "can you do better on space?" after your stack solution. Two pointers is almost always the follow-up.
How to recognize a two-pointer problem in an interview
Ask yourself these three questions when you see an array/string problem:
1. Is the input sorted, or does it have symmetric structure?
Sorted array → probably opposite-ends. Palindrome / bracket matching → symmetric → opposite-ends.
2. Am I filtering, partitioning, or removing in place?
"Remove all X", "move zeroes to end", "deduplicate sorted array" → same-direction (slow/fast).
3. Is there a target value I'm converging on?
"Find two numbers that sum to target" in sorted array → opposite-ends: too big → move right left, too small → move left right.

Visualization trick that helps in interviews:
Before writing any code, draw the array on paper and physically mark L and R. Walk through 2–3 steps by hand. Ask: "when do I move L? when do I move R? when do I stop?" — once you can answer those three, the code writes itself.
