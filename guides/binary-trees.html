Same tree, four visiting orders
Pick a traversal and step through it. The three DFS orders are named for where the root falls relative to its subtrees — pre = before, in = in between, post = after. Left always comes before right; only the root moves. Level order is the odd one out — it's BFS, visiting row by row.

Visit sequence

Preorder — Root, then Left, then Right. Press Step.
Preorder rule
Process the node the moment you arrive, before descending. That's why the root is first.
Why inorder is special for a BST: smaller-left, larger-right means "Left, Root, Right" visits values in sorted order — a free sorted list. That single fact solves Kth Smallest in a BST and Validate BST.
The three DFS orders are the same six lines
You don't learn three algorithms. You learn one recursion and move a single line — where "process this node" sits relative to the two recursive calls. Toggle below to see the line move.

The leap: return information back up (postorder)

    

      
Beginners push info down the tree (preorder: "here's the path so far"). The jump to medium/hard is DFS that returns an answer up from the children and combines it. Height is the template:

    

    
int maxDepth(TreeNode node) {
    if (node == null) return 0;
    int left  = maxDepth(node.left);   // answer for left subtree
    int right = maxDepth(node.right);  // answer for right subtree
    return 1 + Math.max(left, right);  // combine + this node
}

    

      

        
Same shape, different combine

        

          Diameter — track max of leftH + rightH as a side effect.

          Balanced? — return height, or -1 to short-circuit imbalance.

          Max path sum — flow a running sum up, drop negatives.
        

      

      

        
The tell

        
If a node's answer depends on its children's answers, reach for postorder-with-a-return-value. This one pattern is most of the "hard" tree tier.

      

    

    

      Think of a tree as a graph with no cycles — no "visited" set needed, recursion can't loop. Recursion is just DFS with the stack hidden inside the language.

The left<root<right invariant means each comparison lets you throw away half the tree. Pick a target and watch the discarded subtree fade out.

TreeNode search(TreeNode root, int t) {
    while (root != null && root.val != t)
        root = t < root.val ? root.left : root.right;  // discard half
    return root;
}

    

      Where it rots: insert sorted data 1,2,3,4,5 and every value goes right — you build a linked list wearing a tree costume. Height becomes N, search degrades to O(N). This is why self-balancing trees (Red-Black, AVL) exist — and why Java's TreeMap/TreeSet guarantee O(log N) while a hand-rolled BST does not.

How thin the logic really is

    

      

        
Invert a tree (Build/Modify)

        
TreeNode invert(TreeNode n) {
    if (n == null) return null;
    TreeNode t = invert(n.left);
    n.left  = invert(n.right);
    n.right = t;
    return n;
}

      

      

        
LCA in a binary tree

        
TreeNode lca(TreeNode n, p, q) {
    if (n==null||n==p||n==q) return n;
    var L = lca(n.left,  p, q);
    var R = lca(n.right, p, q);
    if (L!=null && R!=null) return n;
    return L != null ? L : R;
}

      

    

    
Both are the DFS skeleton plus three or four problem-specific lines. That's the whole game.


    
The BFS level skeleton (unlocks a whole family)

    
Queue<TreeNode> q = new ArrayDeque<>();
q.offer(root);
while (!q.isEmpty()) {
    int size = q.size();          // freeze THIS level's width
    for (int i = 0; i < size; i++) {
        TreeNode node = q.poll();
        // process node...
        if (node.left  != null) q.offer(node.left);
        if (node.right != null) q.offer(node.right);
    }
}

    

      That q.size() snapshot separates the rows. Tweak the inner loop and you get Right Side View, Zigzag Level Order, and Average of Levels for free.
