The core idea
A sliding window is a contiguous range you carry across the array instead of recomputing. The brute-force way re-sums every subarray from scratch — O(n·k) or O(n²). But consecutive windows overlap almost entirely: when you move one step right, only one element leaves and one enters. Reuse that overlap and you drop to O(n), each element added once and removed at most once.

Two flavours

▭ Fixed window
The width k is given and never changes. Slide it one step at a time: subtract the element that leaves, add the one that enters.

Recognise it when… the problem says "contiguous" subarray / substring and asks for a max, min, longest, shortest, or count over a range. Contiguity is the tell — if elements can be reordered or skipped, it's not a window.
Pattern: slide a fixed width, reuse the overlap
Compute the first window's sum the slow way — once. After that, every slide is two operations: subtract the element leaving on the left, add the element entering on the right. No re-summing. n windows, O(1) work each → O(n) total.

Interactive — max sum subarray of size k (k = 3)

Press step to build the first window.
Decision rule (fixed):
Seed the first window by summing k elements. Then for each new position: sum += arr[right]; sum −= arr[left], advance both edges, and update your best. The whole array is scanned exactly once.
Pattern: expand greedily, shrink only when invalid
right pushes forward every chance it gets, growing the window. The moment the window breaks its rule (here: a repeated character), left shrinks from the back until it's valid again. Record the best length whenever the window is valid.

Interactive — longest substring without repeating characters

Press step. right examines the next char; left shrinks past duplicates.
Decision rule (longest):
Try to add arr[right]. If it keeps the window valid → add it, then update best = max(best, right − left + 1). If it breaks validity → shrink from the left until it's valid again, then add. The answer is the largest valid window ever seen.
Pattern: expand until valid, then squeeze
Mirror image of "longest". Here validity is a target you must reach (sum ≥ target). right expands until the window is valid, then left shrinks as far as it can while staying valid — recording the smallest valid width each time.

Interactive — minimum length subarray with sum ≥ 7

Press step. right adds until sum ≥ target; left shrinks while still ≥ target.
Decision rule (shortest):
If the window is not yet valid → expand right. If it is valid → record best = min(best, width), then shrink left to look for something tighter. Stop when right runs off the end and the window can't be made valid again.
How to recognize a sliding-window problem
Three questions to run through when you see an array or string problem:
1. Is the answer a contiguous run?
"Subarray", "substring", "consecutive", "window of size k" → contiguous → window. If the problem lets you skip or reorder elements, it's not.
2. Is the width given or unknown?
Given a fixed k → fixed window (lockstep slide). Asking for the longest/shortest range that satisfies a rule → variable window (expand/shrink).
3. Can I maintain the window incrementally?
Can one element entering and one leaving update your state in O(1)–O(log n)? A running sum, a char-count map, or a monotonic deque all qualify.

Template skeletons

// Fixed window of size k
int sum = 0, best = 0;
for (int r = 0; r < n; r++) {
    sum += a[r];
    if (r >= k - 1) {
        best = Math.max(best, sum);
        sum -= a[r - k + 1];   // element leaving on the left
    }
}
// Variable window — longest valid
int left = 0, best = 0;
for (int right = 0; right < n; right++) {
    add(a[right]);
    while (!valid())        // broke the rule → shrink
        remove(a[left++]);
    best = Math.max(best, right - left + 1);
}
// Variable window — shortest valid
int left = 0, sum = 0, best = Integer.MAX_VALUE;
for (int right = 0; right < n; right++) {
    sum += a[right];
    while (sum >= target) {   // valid → record & squeeze
        best = Math.min(best, right - left + 1);
        sum -= a[left++];
    }
}
