Recursion is just a stack of paused work
Every call to factorial reserves a stack frame — a little block of memory holding that call's n. Calling itself pushes another frame on top; the caller freezes mid-line, waiting. Step through factorial(n) and watch it wind down to the base case, then unwind up, finishing each multiplication in reverse.

The code

int factorial(int n) {
    if (n <= 1) return 1;        // base case
    return n * factorial(n - 1); // recurse, then multiply
}
The n * runs after the call returns — during unwinding, in reverse order. That "work on the way back up" is post-order traversal, reversing a list, printing a stack.
Miss the base case and the stack never stops growing — that's StackOverflowError. It's almost always a base case that's missing, wrong, or never reached.
Naive fib recomputes the same work — a lot
Naive Fibonacci is a correct recursion that's catastrophically slow: the call tree is fat with duplicate subtrees. Toggle Memoized to cache each answer the first time it's computed — the repeats grey out, and an exponential tree collapses to a linear spine. That single cache is the doorway to dynamic programming.

int fib(int n) {

// O(2ⁿ) — recomputes everything
int fib(int n, Integer[] memo) {
    if (n < 2) return n;
    if (memo[n] != null) return memo[n];
    return memo[n] = fib(n-1,memo)+fib(n-2,memo);
}
// O(n) — each value computed once
Memoization is "recursion + a cache for overlapping subproblems." Fill that cache bottom-up instead of top-down and you've written the iterative tabulation form — that's dynamic programming.
Every recursion is the same five moves
You don't learn a new algorithm per problem. You define the function's contract, find the base case, shrink toward it, trust the smaller call, and combine. The techniques below are that skeleton with a different "combine" step.

Tree / graph DFS — the "same three lines"

void dfs(TreeNode node) {
    if (node == null) return;   // base: fell off the tree
    dfs(node.left);             // trust: handle left subtree
    dfs(node.right);            // trust: handle right subtree
    // visit here → pre/in/post is just WHERE this line sits
}

Backtracking — choose → recurse → un-choose

void subsets(int[] nums, int i, List<Integer> path, List<List<Integer>> out) {
    if (i == nums.length) { out.add(new ArrayList<>(path)); return; }
    subsets(nums, i+1, path, out);          // skip nums[i]
    path.add(nums[i]);                      // choose
    subsets(nums, i+1, path, out);          // recurse
    path.remove(path.size()-1);             // un-choose (backtrack)
}

Divide & conquer — split, solve halves, combine

int[] mergeSort(int[] a) {
    if (a.length <= 1) return a;                       // base
    int mid = a.length / 2;
    int[] l = mergeSort(copyOfRange(a, 0, mid));       // solve each half
    int[] r = mergeSort(copyOfRange(a, mid, a.length));
    return merge(l, r);                                // combine
}
The leap of faith: when you write the recursive call, assume it already returns the right answer for the smaller input. Solve one level, not the whole stack — that's the only way to keep recursion in your head.
